# 비-MVP 백로그

이 문서는 MVP 범위 밖에서 나중에 확장할 기능만 기록한다. 근거는 docs/PRD.md이며, PRD에 없는 기능을 추가하지 않는다. 일정과 실행 계획은 다루지 않는다.

## AI 견적서 추출 (P2)

사용자가 올린 견적서 PDF·이미지를 문서 파싱과 LLM 구조화로 읽어 표준 항목 코드에 자동 매핑하는 기능이다. PRD 5장에서 P2로 정의됐고, 수기 입력 비용을 줄이는 것이 목적이다.

**범위**

- 문서 파싱(OCR 포함)으로 업체명, 날짜, 항목, 금액, 계약조건을 추출한다.
- 추출 결과를 표준 항목 코드에 매핑하고 신뢰도(confidence)를 함께 기록한다.
- 분석은 비동기 job으로 실행하고 결과는 draft JSON으로 보관한다. 문서 분석이 느려도 사용자 흐름을 분리한다.

**document_extractions 테이블**

| 컬럼 | 역할 |
| --- | --- |
| id | 추출 초안 식별자 |
| document_id | 원본 문서 참조 |
| schema_version | 추출 스키마 버전. 모델·프롬프트 변경을 추적한다 |
| raw_json | 파서 원본 출력 |
| confidence | 신뢰도 점수 |
| status | draft / confirmed |

**API와 2단계 확정 플로우**

- POST /api/documents/{id}/extract: AI 분석을 시작하고 draft를 생성한다.
- POST /api/documents/{id}/confirm: 사용자가 검토를 마친 draft를 정식 견적으로 저장한다.
- 플로우는 draft 생성 → 사용자 검토 → confirmed 승격의 2단계다. 승격 시점에 quote와 quote_items가 만들어진다.

**원칙: AI 결과 직접 확정 금지**

AI가 추출한 값은 바로 재무 데이터로 확정하지 않는다. 반드시 draft 상태로 보관하고 사용자 확인 이후 confirmed로 승격한다. 금액 오인식이 예산 판단 오류로 이어지는 것을 막는 최소 안전장치다.

### MVP에서 남긴 확장점

- MVP 스키마는 documents 테이블까지만 포함하고 document_extractions는 분리해 뒀다. 추출 기능을 붙일 때 기존 견적·문서 테이블을 건드리지 않는다.
- documents의 ai_status 필드로 문서별 분석 상태만 표시하고, 초안 데이터 본체는 확장 시점에 새 테이블로 들어온다.
- 표준 항목 코드(item-codes 상수)를 먼저 고정해 뒀기 때문에 AI 매핑 로직은 코드 체계 위에 얹기만 하면 된다.

## 확장 모듈

결혼 준비 프로세스 단계 5~7에 해당하는 신혼여행, 혼수/가전, 신혼집이다. PRD 2장은 이 셋을 "코어 MVP 이후 모듈로 확장"한다고 명시한다.

- 신혼여행: 지역, 일정, 항공, 숙박, 액티비티. 여행일정과 예약금액을 관리한다.
- 혼수/가전: 품목, 가격, 구매순서, 배송일을 관리한다.
- 신혼집: 매매/전세/월세, 지역, 보증금, 대출을 관리하며 국토부 실거래가를 참고 데이터로 쓴다.

각 모듈은 코어의 예산 카테고리와 항목 코드 체계를 그대로 쓴다. 모듈 데이터는 코어 스키마와 섞지 않고 별도 테이블로 추가한다.

### MVP에서 남긴 확장점

- src/lib/constants/item-codes.ts의 표준 항목 코드 체계를 카테고리별 코드 추가가 가능한 구조로 정의해 뒀다.
- budget_categories의 code 컬럼이 문자열 식별자라서 모듈 추가 시 카테고리 코드만 늘리면 된다.
- quote·quote_items 구조를 웨딩홀 전용 필드 없이 일반 항목 구조로 설계해 뒀기 때문에 다른 모듈의 견적과 지출에도 재사용된다.

## 외부 데이터

PRD 4장에서 우선순위 C로 분류된 두 소스다. 외부 데이터는 정답이 아니라 기준선이며, 의사결정은 사용자가 받은 실제 견적을 중심으로 한다.

- 국토교통부 아파트 매매 실거래가(REST/XML): 법정동 코드와 계약년월로 조회한다. 신혼집 모듈의 지역 가격 분석에 쓴다.
- 한국관광공사 TourAPI(REST): 국내 신혼여행의 관광지·숙박 후보를 조회한다. 신혼여행 모듈과 함께 붙는다.

외부 포맷은 바뀔 수 있다. source adapter로 변경을 도메인에서 분리하고 원본 응답(raw snapshot)을 보관해 배치 실패에 대비한다. 이용약관과 호출 한도, 재배포 범위는 구현 시점에 각 제공기관의 최신 정책을 다시 확인한다.

### MVP에서 남긴 확장점

- src/lib/adapters/의 외부 데이터 어댑터 인터페이스를 MVP에서 정의해 둔다. 새 소스는 구현체 추가만으로 붙는다.
- MVP 스키마의 price_benchmarks가 source 컬럼을 소스 식별자로 갖는다. 실거래가·TourAPI 추가 시 스키마 변경 없이 데이터만 쌓인다.

## 향후 인프라

- 파일 저장소: MVP는 로컬 디스크 구현체로 운영하고 이후 S3로 교체한다. 원본 파일과 DB 메타데이터를 분리하는 구조는 PRD 11장 권장 설계를 따른다.
- 배포·CI: 공용 게이트(lint, typecheck, test)를 CI에서 자동 실행하고 배포 파이프라인에 연결한다.
- 자동 배치 임포트: 참가격 기준선을 주기적으로 적재하는 benchmark import job을 둔다. MVP에서는 수동 임포트로 시작한다.

### MVP에서 남긴 확장점

- StorageAdapter 인터페이스와 로컬 디스크 구현체가 S3 교체 지점이다. 인터페이스를 유지하면 구현체 교체와 설정값 추가만으로 옮겨간다.
- 문서 원본은 파일로, 메타데이터는 documents 테이블로 분리해 뒀다. 저장소가 바뀌어도 file_url 참조 방식만 바꾸면 된다.
- 벤치마크 임포트는 수동 실행 스크립트 형태로 남겨 둔다. 자동화 시점에 스케줄러만 얹는다.
